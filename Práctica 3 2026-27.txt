2. Introducción a MPI
MPI (Message-passing interface) es una especificación que establece las funciones de una
biblioteca para el paso de mensajes entre múltiples procesadores. Esto permite la
comunicación vía paso de mensajes entre nodos de un clúster de computadores que
constituyen sistemas multicomputador de memoria distribuida1. En este escenario los datos
utilizados por un proceso se mueven desde el espacio de direcciones de este al de otro proceso,
de forma cooperativa, mediante las instrucciones recogidas en el estándar MPI.
Podemos distinguir 4 tipos de instrucciones definidas en la especificación de MPI:
1. Instrucciones para abrir, gestionar y cerrar las comunicaciones entre procesos corriendo
en diferentes nodos.
2. Instrucciones para transferir datos entre 2 procesos (uno a uno).
3. Instrucciones para transferir datos entre múltiples procesos.
4. Instrucciones que permiten al usuario definir tipos de datos.
Las principales ventajas del uso de MPI son que permite establecer un estándar de paso de
mensajes en arquitecturas multicomputadora portable, fácil de utilizar y que permite abstraer
los detalles de bajo nivel propios de la gestión de este tipo de comunicaciones.
Existen multitud de librerías que implementan el estándar MPI (mpich, OpenMPI, …) en
diferentes lenguajes como c, c++, Fortran, Python etc.. En este enlace podéis encontrar un
tutorial con ejemplos de uso de MPI del laboratorio Lawrence-Livermore.

Tarea 1. Análisis del rendimiento secuencial mediante gprof
Antes de comenzar la paralelización de cualquier programa, es necesario identificar qué
funciones consumen más tiempo de ejecución y, por tanto, cuáles son las principales
candidatas a optimización. Para ello, utilizaremos gprof, una herramienta de profiling de GNU
que permite analizar el tiempo de CPU consumido por cada función, el número de veces que se
invoca y el tiempo medio por llamada. Además, proporciona un grafo de llamadas (call graph)
que permite identificar las relaciones entre las distintas funciones del programa.
Para utilizar gprof, es necesario compilar y enlazar el programa con la opción -pg, que habilita
la instrumentación necesaria para registrar las llamadas a funciones. Se recomienda utilizar
también -g para incluir información de depuración y -O0 para evitar que las optimizaciones del
compilador, especialmente el inlining, dificulten la identificación de las funciones:
gcc -O0 -g -pg programa.c -o programa
En programas C++, se utilizará g++ en lugar de gcc. Si el programa contiene varios archivos
fuente, todos deberán compilarse con -pg, y esta opción también deberá incluirse durante el
enlazado.
A continuación, se ejecuta normalmente el programa:
./programa
Al finalizar, se generará un archivo denominado gmon.out, que contiene la información
recogida durante la ejecución. Para analizarla y generar un informe, se utilizará:
gprof -b -p -q ./programa gmon.out > perfil.txt
Las opciones utilizadas permiten obtener:
•
•

•

-b: elimina las explicaciones generales del informe para facilitar su lectura.
-p: genera el perfil plano (flat profile), que incluye el tiempo de CPU atribuido a cada
función, su porcentaje respecto al total, el número de llamadas y el tiempo medio por
llamada.
-q: genera el grafo de llamadas (call graph), que muestra las relaciones entre funciones
y el tiempo atribuido a cada una, incluyendo sus llamadas a otras funciones.

A partir de estos resultados, se deberán identificar las funciones que concentran la mayor parte
del tiempo de ejecución, distinguiendo entre aquellas que se ejecutan muchas veces y aquellas
cuyo coste individual es elevado. Los tiempos proporcionados por gprof son estimaciones
basadas en muestreo, mientras que el número de llamadas se obtiene mediante
instrumentación. Por tanto, los resultados deben interpretarse como una aproximación al
comportamiento del programa y utilizarse para justificar qué partes del código conviene
estudiar para su posterior paralelización mediante MPI.

Tarea 2. Ejecución distribuida de código MPI
Introducción a MPI
Antes de emprender la paralelización de los problemas propuestos, es necesario familiarizarse
con el funcionamiento de MPI, para ello, ejecutaremos un código de ejemplo sencillo, a modo
de ‘hola mundo’ paralelo. Este es el código a compilar:
#include <stdio.h>
#include "mpi.h"
#include <unistd.h>
#include <stdlib.h>
int sched_getcpu();
int main(int argc, char *argv[]) {
int numprocs, rank, namelen;
char processor_name[MPI_MAX_PROCESSOR_NAME];
MPI_Init(&argc, &argv);
MPI_Comm_size(MPI_COMM_WORLD, &numprocs);
MPI_Comm_rank(MPI_COMM_WORLD, &rank);
MPI_Get_processor_name(processor_name, &namelen);
printf(" PID: %d Hello from process %d out of %d on %s processor %d \n",
getppid(), rank, numprocs, processor_name, sched_getcpu());
if (rank==2)
{
printf("¡Hola! desde el procesador %d\n", rank);
}
MPI_Finalize();
}

Tutorial de compilación con MPI
1. Todas las máquinas deben tener el mismo usuario. Todos los ejecutables deben tener
el mismo nombre en cada máquina y estar en la misma carpeta.
2. Compilad empleando mpicc o mpic++:
mpicc programa.c -o programa

Recordad que el programa, junto con sus dependencias, deben copiarse y ser accesibles en
cada nodo de su multicomputador.
3. Cread el archivo de hosts con las IPs o nombres de cada nodo de la red y copiar al resto
de máquinas en el mismo directorio de trabajo donde se encuentran los ejecutables.
Archivo de hosts: archivo de texto plano que especifica el nombre o la IP de las máquinas que
forman el supercomputador. Cada nombre/IP en una línea.
4. Cree un certificado de clave pública SSH en uno de los nodos:
ssh-keygen -t rsa

Cread la carpeta oculta ~/.ssh.
5. Copiad el archivo ~/.ssh/id_rsa.pub en la carpeta ~/.ssh del resto de máquinas y
cambiad su nombre a authorized_keys. Si no existe la carpeta oculta ~/.ssh en una
máquina, creadla previamente ejecutando el comando:
ssh-keygen -t rsa

6. Ejecutad el programa en la máquina donde se creó el certificado:
mpirun -mca plm_rsh_no_tree_spawn 1 -hostfile <archivo_hosts> -n <núm_procesos> ./programa

Observaciones
•

Usad el mismo directorio en todas las máquinas: p. ej., carpeta personal ($HOME).

•

Abrid sesión con el mismo usuario en todos los nodos del clúster.

•

Puede ser necesario modificar los permisos de los archivos:

Archivo de hosts:
chmod 600 <archivo_hosts>

Archivo ejecutable para permitir ejecución remota:
chmod o+x programa

El objetivo es aplicar los conceptos de programación paralela mediante paso de mensajes,

Contexto del problema
El objetivo de esta práctica es paralelizar un programa que realiza el entrenamiento, ajuste de
hiperparámetros y evaluación de un clasificador k-Nearest Neighbors (kNN) mediante técnicas
de validación cruzada (cross-validation) y búsqueda de hiperparámetros (fine-tuning).
Para ello, utilizaremos el conjunto de datos MNIST, ampliamente empleado en tareas de
reconocimiento de caracteres mediante técnicas de visión por computador. Este conjunto
contiene imágenes de dígitos manuscritos (del 0 al 9) y está formado por 60.000 muestras de
entrenamiento y 10.000 muestras de prueba.

Aprendizaje automático (Machine Learning)
El aprendizaje automático es una rama de la inteligencia artificial cuyo objetivo es desarrollar
algoritmos capaces de aprender patrones a partir de datos y utilizarlos para realizar tareas sin
necesidad de programar explícitamente todas las reglas que deben seguir.
Una de sus aplicaciones más habituales es la clasificación, que consiste en asignar cada
muestra de entrada a una de las categorías previamente definidas.
Según la información disponible durante el aprendizaje, podemos distinguir tres enfoques
principales:
1. Aprendizaje supervisado: el algoritmo utiliza un conjunto de muestras previamente
etiquetadas. Su objetivo es aprender las características que permiten distinguir unas
categorías de otras y utilizar ese conocimiento para clasificar nuevas muestras.
2. Aprendizaje no supervisado: el algoritmo trabaja con muestras que no disponen de
etiquetas y trata de identificar patrones, similitudes o estructuras presentes en los datos.
Por ejemplo, puede agrupar muestras con características semejantes.
3. Aprendizaje semisupervisado: combina muestras etiquetadas y no etiquetadas
durante el proceso de aprendizaje, aprovechando la información de ambos conjuntos.

Evaluación de clasificadores
Para evaluar el rendimiento de un clasificador existen diferentes métricas, entre las que
destacan la exactitud (accuracy), la precisión (precision) y la sensibilidad (recall). Estas
métricas permiten cuantificar hasta qué punto el clasificador asigna correctamente las
categorías a las muestras analizadas.
Sin embargo, obtener buenos resultados sobre los datos utilizados durante el entrenamiento no
garantiza que el clasificador funcione correctamente con muestras nuevas. Uno de los
problemas más habituales es el sobreajuste (overfitting), que se produce cuando un modelo se
adapta excesivamente a los datos de entrenamiento y pierde capacidad de generalización.
Para evaluar correctamente un clasificador, el conjunto de datos suele dividirse en dos
subconjuntos:
•

Conjunto de entrenamiento (training set): se utiliza para construir o ajustar el
clasificador.

•

Conjunto de prueba (test set): se utiliza para evaluar su rendimiento final con muestras
que no han participado en el proceso de entrenamiento o ajuste.

Además, durante el desarrollo del clasificador es habitual reservar una parte de los datos de
entrenamiento como conjunto de validación (validation set). Este conjunto permite comparar
distintas configuraciones del clasificador y seleccionar los valores de sus hiperparámetros sin
utilizar los datos de prueba.

Validación cruzada (Cross-Validation)
La validación cruzada es una técnica que permite evaluar de forma más robusta el rendimiento
de un clasificador utilizando diferentes particiones de los datos disponibles.
En lugar de realizar una única división entre entrenamiento y validación, se repite el proceso
utilizando distintos subconjuntos. El rendimiento final se estima combinando los resultados
obtenidos en las distintas evaluaciones, habitualmente mediante su media.
Entre las técnicas de validación cruzada destacan las siguientes:
1. Validación cruzada de N particiones (N-Fold Cross-Validation): el conjunto de datos
se divide en N subconjuntos, denominados folds. Se realizan N evaluaciones y, en cada
una de ellas, se utiliza un subconjunto diferente como conjunto de validación, mientras
que los N−1 restantes se emplean para el entrenamiento. De este modo, cada muestra
participa una vez en la validación.
2. Validación dejando uno fuera (Leave-One-Out Cross-Validation): es un caso
particular de la validación N-Fold en el que N coincide con el número de muestras
disponibles. En cada evaluación se utiliza una única muestra para validar el clasificador

Clasificador k-Nearest Neighbors (kNN)
El clasificador k-Nearest Neighbors (kNN) es uno de los algoritmos de clasificación supervisada
más sencillos.
Su funcionamiento se basa en una idea intuitiva: las muestras que presentan características
similares suelen pertenecer a la misma categoría. Por tanto, para clasificar una nueva muestra,
el algoritmo busca las K muestras más próximas a ella dentro del conjunto de entrenamiento y
determina su categoría a partir de las etiquetas de esos vecinos.
El procedimiento de clasificación consta de los siguientes pasos:
1. Calcular la distancia entre la muestra que queremos clasificar y cada una de las
muestras del conjunto de entrenamiento.
2. Identificar las K muestras que se encuentran a menor distancia.
3. Determinar la categoría más frecuente entre esos K vecinos.
4. Asignar dicha categoría a la nueva muestra.
El valor de K es un hiperparámetro fundamental del clasificador. Un valor pequeño puede hacer
que el resultado sea muy sensible al ruido o a muestras atípicas, mientras que un valor elevado
puede provocar que se pierdan diferencias relevantes entre categorías.
A diferencia de otros algoritmos de aprendizaje automático, kNN no necesita construir un
modelo explícito durante una fase de entrenamiento. En su forma más sencilla, el
entrenamiento consiste únicamente en almacenar las muestras etiquetadas que
posteriormente se utilizarán para realizar las clasificaciones.
Esta característica facilita la incorporación de nuevas muestras e incluso de nuevas categorías
sin necesidad de volver a entrenar un modelo. Por ejemplo, en una aplicación de
reconocimiento facial, podrían incorporarse nuevos usuarios añadiendo imágenes etiquetadas
de sus rostros al conjunto de entrenamiento.
Sin embargo, esta sencillez tiene una contrapartida importante: el coste computacional se
concentra en la fase de clasificación, ya que, para cada nueva muestra, es necesario calcular
las distancias respecto a las muestras almacenadas.
Este comportamiento convierte a kNN en un candidato interesante para estudiar distintas
estrategias de paralelización, tanto mediante la distribución de muestras entre procesos como
mediante la descomposición de las operaciones necesarias para clasificarlas.

Ajuste de hiperparámetros (Fine-Tuning)
Los clasificadores suelen disponer de hiperparámetros que permiten adaptar su
funcionamiento a las características de cada problema.
En la implementación de kNN que utilizaremos en esta práctica, consideraremos un único
hiperparámetro: el número de vecinos K.
El objetivo del ajuste de hiperparámetros es encontrar el valor de K que proporciona el mejor
rendimiento de clasificación.
Una estrategia habitual consiste en realizar una búsqueda exhaustiva (grid search), evaluando
sistemáticamente diferentes valores de los hiperparámetros mediante validación cruzada.
En nuestro caso, el procedimiento será el siguiente:
1. Seleccionar un conjunto de posibles valores de K.
2. Realizar una validación cruzada para cada valor de K.
3. Obtener una estimación del rendimiento del clasificador para cada configuración.
4. Comparar los resultados y seleccionar el valor de K que proporciona el mejor
rendimiento.
El resultado de este proceso será un vector que contendrá una medida de rendimiento para
cada valor de K evaluado.
Si un clasificador tuviera varios hiperparámetros, la búsqueda exhaustiva evaluaría diferentes
combinaciones de sus valores, dando lugar a una estructura de resultados multidimensional.

Caso especial: paralelismo funcional y ejecución especulativa
Además del paralelismo de datos que puede identificarse en diferentes partes del algoritmo,
esta práctica plantea un caso especial cuyo objetivo es explorar el paralelismo funcional, la
comunicación entre procesos y la ejecución especulativa.
En una implementación convencional, las fases de ajuste de hiperparámetros y evaluación final
del clasificador se ejecutan secuencialmente:
1. Se evalúan distintos valores de K mediante validación cruzada.
2. Se selecciona el valor de K que proporciona el mejor rendimiento.
3. Se utiliza ese valor para realizar la evaluación final del clasificador sobre el conjunto de
prueba.
Existe, por tanto, una dependencia entre ambas fases: no podemos realizar la evaluación final
con el valor óptimo de K hasta que haya terminado el proceso de ajuste.

Para explorar una estrategia alternativa, vamos a forzar la ejecución concurrente de ambas
fases mediante procesos MPI, utilizando un mecanismo de ejecución especulativa.
El funcionamiento propuesto será el siguiente:
1. Un conjunto de procesos se encargará de realizar el ajuste de hiperparámetros,
evaluando diferentes valores de K.
2. Simultáneamente, otro conjunto de procesos comenzará a realizar la evaluación final
utilizando el mejor valor de K conocido hasta ese momento.
3. Cuando el proceso de ajuste encuentre un nuevo valor de K que mejore los resultados
anteriores, deberá comunicarlo a los procesos responsables de la evaluación mediante
paso de mensajes.
4. Si la evaluación está utilizando un valor de K que ha dejado de ser el mejor conocido,
deberá invalidar el procesamiento en curso y reiniciarlo con el nuevo valor.
5. Cuando termine el ajuste de hiperparámetros, la evaluación final deberá haberse
realizado correctamente utilizando el valor óptimo de K encontrado.
Esta estrategia es especulativa porque la evaluación final comienza utilizando un valor de K que
todavía no sabemos si será el definitivo.
Si el valor utilizado resulta ser el óptimo, habremos conseguido solapar parte de las dos fases y
reducir el tiempo total de ejecución. Por el contrario, si el mejor valor de K cambia
repetidamente, será necesario descartar trabajo ya realizado, lo que puede reducir o incluso
eliminar las ventajas de la paralelización.
El objetivo será analizar si el paralelismo funcional puede proporcionar una mejora de
rendimiento suficiente para compensar los costes adicionales de comunicación,
sincronización y procesamiento especulativo.
La implementación deberá tener en cuenta que los procesos MPI disponen de espacios de
memoria independientes. Por tanto, cualquier información que necesite compartirse entre
procesos, como los resultados parciales de validación, los mejores valores de K o las señales
de finalización, deberá intercambiarse mediante mecanismos de comunicación explícitos.
